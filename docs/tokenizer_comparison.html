Where the token boundaries fall

Both arms cut the same 10-second ECG into tokens of the same length. The only difference is where the cuts land — on a clock, or on the heartbeat. Everything below is drawn from real PTB-XL records with R peaks from the actual detection pipeline.

    The count matches at the median, and only there. 833 ms is 10 s ÷ 12, and the median PTB-XL record holds 12 beats, so both arms produce about 144 tokens across 12 leads. That was chosen deliberately — if the arms differed in sequence length as well as boundary placement, a win for either could be explained by the extra tokens instead of the tokenization. But the match holds only at the median, and the extremes below show what happens when it does not.

    What the extremes break

    A fixed 833 ms window is right for a heart beating near 72 bpm and wrong in both directions away from it. Switch to the bradycardic and extreme records above and watch the strips: the failures are visible, and they are not the same failure.

    Slow — the window is shorter than the beat

    At 47.7 bpm the RR interval is 1258 ms but the window spans only 833 ms, so mid-diastole falls outside every token. Nothing is clipped; signal is simply never reached.

     

    Fast — the beat is shorter than the window

    At 175.8 bpm the RR interval is about 341 ms. Every window is clipped hard at the midpoints and the rest of the buffer is padding the model must be masked away from.

     
    signal inside a token signal in no token padding inside a token

    How often this bites. Measured across 1,499 records of the cleaned cohort: below 50 bpm the RR arm reaches only 62% of the signal, and 7.6% of records sit at or below 55 bpm. Above 140 bpm the buffer is under half full, though only 0.7% of records get that fast. Sequence length runs from 84 to 336 tokens against the fixed arm's constant 144, and 0.9% of records exceed a 252-token budget.

    A symmetric window is the wrong shape. The R peak is not in the middle of a beat's information: the P wave sits roughly 200 ms before it, while the T wave runs to about 460 ms after it at 50 bpm. A window of −417/+417 ms therefore clips the T wave on slow beats — which is ST-T territory, the STTC class — while spending room before the P wave on nothing. Shifting the same 833 ms buffer to roughly −333/+500 ms would cover the full PQRST at bradycardic rates at no extra cost, and would leave only genuinely quiet diastole outside the tokens. This is a proposal, not something already decided.

    One token, close up

    Each RR token wants 833 ms centred on its R peak. Where a neighbour is closer than that, the window is clipped at the midpoint between the two beats and the remainder is zero-padded — so tokens tile the record exactly and never overlap.

      Why clip instead of letting windows overlap. Free-floating 833 ms windows would overlap whenever the heart rate exceeds 72 bpm. In masked-reconstruction pretraining that overlap is a leak: the model recovers a masked token by reading its neighbour, and the task collapses. Clipping at the midpoint removes the leak and keeps every sample in exactly one token.

      Why these tokens are not resampled

      The earlier design resampled every RR interval to a fixed number of samples. These are two real beats — one tachycardic, one bradycardic — with a 100 ms band drawn over each R peak, the width of a normal QRS complex.

      Real time — what we do now

      Same milliseconds per pixel in both. The 100 ms band is the same width in both, because a QRS complex is the same width at any heart rate.

      QRS width reads as 100 ms in both

      Resampled to equal token width — rejected

      Both intervals stretched to the same token length. The band is unchanged in the signal, but now occupies a very different share of the token.

      QRS appears wider at speed

      This is why it matters for conduction disorder. CD is defined in absolute milliseconds — a right bundle branch block is QRS ≥ 120 ms, first-degree AV block is PR > 200 ms. After resampling, the model can only recover those durations by multiplying a relative width by the RR value fed alongside it. That burden falls on the RR arm alone, on the very class beat alignment is supposed to win. Keeping real time removes it.
